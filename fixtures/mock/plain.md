=== oauth-explain ===
## OAuth 2.0 の認可コードフロー

OAuth 2.0 は、ユーザーのパスワードをアプリに渡さずに、アプリへ権限を委ねる仕組みです。登場する役割は 4 つあります。

- ユーザー: 自分のデータへのアクセスを許可する人
- クライアントアプリ: ユーザーの代わりにデータを使いたいアプリ
- 認可サーバー: ユーザーの同意を確認し、トークンを発行するサーバー
- リソースサーバー: 実際のデータを持つ API

流れは次のとおりです。

1. アプリがユーザーを認可サーバーのログイン画面へ送ります。
2. ユーザーがログインし、アプリへの許可に同意します。
3. 認可サーバーは「認可コード」を付けて、ユーザーをアプリへ戻します。
4. アプリはサーバー側から、認可コードとクライアントシークレットを認可サーバーへ送ります。
5. 認可サーバーはアクセストークンを返します。
6. アプリはアクセストークンを付けてリソースサーバーの API を呼びます。

なぜトークンを直接返さないのでしょうか。ステップ 3 はブラウザ経由なので、URL が履歴やログに残ります。ここにトークンがあると漏れたときの被害が大きくなります。認可コードは一度しか使えず、有効期限も短いうえ、交換にはクライアントシークレットが必要です。そのため、コードが漏れてもトークンは取れません。

# 開発環境のセットアップ

## 1. Node.js と pnpm を入れる
Node.js 22 以上と pnpm が必要です。次のコマンドでバージョンを確認します。

```
node --version
pnpm --version
```

## 2. リポジトリを取得する
```
git clone <repo-url>
cd <repo>
pnpm install
```

## 3. 環境変数を設定する
`.env.example` をコピーして `.env` を作り、API キーを書き込みます。

## 4. テストで確認する
`pnpm test` を実行します。すべて通れば準備完了です。

## よくあるエラー
- **pnpm が見つからない**: `npm install -g pnpm` で入れてください。
- **ポート 3000 が使用中**: 他のプロセスを止めるか、`PORT=3001 pnpm dev` のように別のポートを指定してください。

1. ログイン画面の「パスワードをお忘れですか？」を押します。

# 通知配信を非同期化する

## 背景
通知先サービスの遅延が、そのまま API の応答時間に影響していました。ピーク時にはタイムアウトが増えていました。

## 決定
通知配信を、同期的な API 呼び出しからメッセージキュー経由の非同期処理に変更します。

## 理由
次の 3 案を検討しました。
- (a) 現状維持でタイムアウトを延ばす: 根本原因が残ります。
- (b) キューを導入する: 応答時間を通知先の遅延から切り離せます。再送も仕組みとして持てます。
- (c) 通知先サービスを内製化する: 工数が大きすぎます。

(b) を採用します。

## 影響
- 通知は最大で数秒遅れます。
- 配信状態を確認する API を追加します。
